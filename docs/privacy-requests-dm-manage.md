# 부서 관리(dep-manage) 개인정보 보강 수정 요청

작성: 2026-11-17 (교적 관리 ch-manage 세션) · 이 파일은 **dep-manage 세션에 그대로 붙여 넣어** 수정을 지시하는 용도입니다.
짝 파일: docs/privacy-requests-fin-manage.md (재정 관리용)

> 이 문서의 법령 내용은 웹 검색으로 확인한 요약이며 **조문 원문을 직접 읽은 것이 아닙니다.** 법률 자문이 아닙니다.
> "확인 필요"로 표시한 것은 법제처(law.go.kr)·개인정보보호위원회(privacy.go.kr) 원문 확인 후 적용하세요.
> **지시 방식**: 아래 2번의 항목을 우선순위 순서로 진행하되, 설계가 필요한 항목(동의 기록 등)은 구현 전에 **설계안을 사용자에게 먼저 보여 주고 확인**을 받으세요. 커밋·푸시·배포는 사용자가 말할 때만 하세요. 2단계 인증은 이번 범위에서 **제외(보류)** 입니다.

## 1. 공통 배경 (법 기준과 교적이 정한 약속)

### 적용되는 법과 기준
| 구분 | 요구 | 근거 |
|---|---|---|
| 처리방침 | 모든 개인정보처리자가 수립·공개 | 개인정보 보호법 제30조 |
| 보호책임자 | 지정하고 연락처 공개 | 제31조 |
| 민감정보 | 종교 관련 정보는 민감정보로 보는 것이 일반적. 별도 동의 | 제23조 |
| 14세 미만 | 법정대리인 동의 | 제22조의2 |
| 국외 이전 | 이전받는 자·국가·시기·방법·항목·목적·보유기간·거부 방법 공개 | 제28조의8 |
| 파기 | 목적이 끝나면 지체 없이 | 제21조 |
| 접속기록 | **1년 이상, 민감정보·고유식별정보를 처리하는 시스템은 2년 이상.** 항목: 계정, 접속일시, **접속지 정보(IP)**, 처리한 정보주체 정보, 수행 업무 | 안전성 확보조치 기준 제8조 (확인 필요: 2년 기준 세부) |
| 접근권한 변경 기록 | 부여·변경·말소 내역 **3년 이상** | 같은 기준 제5조 제3항 (확인 필요) |
| 유출 | 정보주체 통지 + 일정 규모 이상 신고(1천 명 이상 등) | 제34조 (통지 기한이 자료마다 24시간·72시간으로 달라 **원문 확인 필요**) |

2026년 9월 11일 시행된 개정 보호법: 과징금 강화, 유출 통지 범위 확대(랜섬웨어 등 포함), 대표자 책임 강화. 교회에 어디까지 적용되는지는 확인하지 못함.

### 교적(ch-manage)이 정한 공통 약속 — 두 프로그램도 맞춰 주세요
1. **책임자·문의처는 교적의 교회 정보에서 가져옵니다.** 교적 0.1.1부터 `cm_site_settings.church_info` JSON 에 새 칸이 있습니다.
   - `privacyOfficer` (개인정보 보호책임자: 직책·이름), `privacyPhone`, `privacyEmail`
   - 비어 있으면 `phone`, `email`(교회 대표 전화·이메일)로 대신합니다. 교적은 `/auth/me` 응답에 이미 `privacy: {officer, phone, email}` 로 합쳐서 내려 줍니다. (읽기만 하세요. 쓰지 마세요.)
2. **접속·수정 기록 보관은 최소 2년.** 교적은 기본 3년, 설정 범위 2~10년.
3. **처리방침 판(시행일)** 은 `YYYY-MM-DD` 하나로 관리하고, 방침 화면의 날짜와 동의 기록의 "처리방침 판"이 같은 값을 쓰게 합니다. (교적: `POLICY_VERSION = '2026-11-17'`)
4. 방침에 **개정 이력** 목록을 둡니다(날짜 · 한 줄 요약).
5. 접속 기록에는 접속 주소(IP)를 남깁니다.
6. **2단계 인증은 보류**입니다(이번 요청에 포함하지 않음).

## 2. 수정 요청 (부서 관리)

### 배경
부서 관리는 **어린이·청소년(상당수 14세 미만)** 의 이름·생년월일·학교·보호자 연락처·출석·**기도 제목**·심방 기록을 다룹니다. 신앙 관련 정보와 14세 미만 정보가 섞여 있어 법 기준이 엄격하게 적용됩니다. 현재 `web/src/routes/privacy/+page.svelte` 방침과 `audit_log`(IP 포함) 는 이미 있습니다. 아래는 법·교적과 어긋나는 부분입니다.

### 수정 요청 (우선순위 순)

**D-1. 접속·작업 기록 보관 기간 문구를 "2년 이상"으로 바로잡기** — 방침 7번(보유 및 이용 기간)에 "법령에서 정한 접속기록 보관 기간(최소 1년)을 지킵니다"라고 되어 있습니다. 이 프로그램은 신앙 정보(기도 제목 등)와 14세 미만 정보를 다루므로 **2년 이상**으로 고치세요. `audit_log` 를 지우는 코드는 현재 없는 것으로 보이니(로그인 시도 기록만 하루 뒤 삭제) 실제 동작과 문구가 맞는지 확인하고, 앞으로 정리 기능을 만들면 **최소 2년 미만으로 줄일 수 없게** 하세요.

**D-2. 열람·내려받기 기록 확인** — 법은 "처리한 정보주체 정보와 수행 업무"를 남기라고 합니다. 방침에는 "주요 작업 기록(누가 언제 무엇을 바꾸었는지)"이라고 되어 있어 **조회(열람)·엑셀 내려받기·출력**이 `audit_log` 에 남는지 확인하세요. 남지 않으면 추가: 학생·교사 상세 열람, 명단 엑셀 내려받기, 출석 통계·기도 제목·심방 기록 열람, 사진 열람. (대상 `target_type/target_id`, 사용자, IP, 시각)

**D-3. 개인정보 동의 기록 기능 추가 (설계안 먼저 사용자에게 보여 주고 확인받기)** — 지금 부서 관리에는 동의를 기록하는 곳이 없습니다. 교적에는 `cm_consents` 표가 있습니다(아래 참고). 요구 사항:
- 학생·교사별 동의 기록: 종류(개인정보 수집·이용 / **보호자 동의(14세 미만)** / 사진·영상 / 문자 수신), 동의일, 방법(서면·구두·앱), 보호자 이름·관계, 처리방침 판, 철회일.
- 14세 미만인데 **보호자 동의가 없는 학생 목록** 화면(대시보드의 "챙길 일"에 개수 표시).
- 교적과 연결된 학생은 같은 사람의 `cm_consents` 와 **중복·충돌하지 않게**: 교적 기록을 읽어 표시하고, 부서 쪽에서 남긴 동의도 교적 카드에서 보이게 할지(같은 표 사용 vs 별도 `dm_consents`)를 설계에서 정하세요. 교적 표 구조는 아래 부록.
- 부모 동의서 서식은 교적 `docs/privacy-forms.html`(2쪽) 을 부서용으로 가져가 쓰세요.

**D-4. 파기(보유 기간) 방식 보완** — 방침 7·8번이 "졸업·전출·활동 종료 후 삭제 요청이 없으면 '활동 종료' 상태로 두고 필요 없어지면 삭제"라고 되어 있어 **기간이 정해져 있지 않습니다.** 법은 보유 기간을 정해 알리고 지나면 지체 없이 파기하라고 합니다. 교적의 방식을 따라 "활동 종료 N년 뒤(기본 5년, 1~30년 설정) 연락처·주소·보호자 정보·기도 제목·메모·사진을 지우고, 이름·반·출석 통계 같은 기록만 남긴다"를 추가하는 것을 제안합니다. 방침 문구와 함께 고치세요. (교적 `retention_purge` 참고)

**D-5. 보호자 정보(제3자 정보) 수집 안내** — 학생 정보에 보호자 이름·연락처가 들어갑니다. 방침 1번 항목에 "보호자 정보를 학생 등록 때 함께 받는다"는 점과 보호자 동의 방법을 명시하세요.

**D-6. 방침에 개정 이력 + 판 번호** — 시행일 `YYYY-MM-DD` 한 곳에서 관리(`EFFECTIVE` 상수가 있다면 그것), "개정 이력" 목록 추가. 이번 개정 내용(접속기록 2년 이상, 동의 기록 안내, 파기 기간)을 한 줄로 적으세요.

**D-7. 책임자·문의처를 교적 새 칸에서 가져오기** — `privacyOfficer`, `privacyPhone`, `privacyEmail`(없으면 `phone`, `email`)을 읽어 방침 12번에 표시. 교적이 없는 단독 설치면 기존 "관리책임자 설정"을 그대로 쓰세요.

**D-8. 방침과 실제 동작 일치 확인** — 국외 이전 "하지 않음"이라고 적혀 있습니다. 사진 올리기, 문자, AI 분석 등 **외부로 정보를 보내는 기능이 하나라도 있는지** 확인하세요(검색으로는 Gemini·솔라피 사용 흔적이 없었음). 있다면 국외 이전·위탁 표를 추가(교적 방침 6번 참고).

**D-9. 매뉴얼에 운영 안내 추가** — 매뉴얼(프로그램 안)에 "개인정보 운영" 항목: 동의서 받기, 졸업 후 정리, 유출 의심 시 대응. 교적 `docs/privacy-forms.html`(3쪽 유출 대응, 4쪽 연간 점검표) 링크 또는 내용 활용.

### 확인 방법(수정 후)
- 접속 기록이 열람·내려받기까지 남는지 직접 확인
- 방침 화면: 접속기록 "2년 이상", 보유 기간 수치, 개정 이력, 책임자·문의처 표시
- 14세 미만·동의 누락 목록이 맞는 사람만 나오는지
- 교적과 같은 DB에 설치된 상태에서 동의 표 충돌이 없는지

## 3. 교적(ch-manage)에서 한 일 (참고)

| 번호 | 내용 |
|---|---|
| 1 | 접속·수정 기록 보관 설정 최소 **2년**(서버 `LOG_YEARS_MIN`, 화면 입력칸 min=2). 예전에 1년으로 저장돼 있어도 읽을 때 2년으로 보정 |
| 2 | 접속 기록에 **접속 주소(IP)** 추가(마이그레이션 008, 구조 번호 8). 관리자 화면 접속 기록 표에 "접속 주소" 열 |
| 3 | 처리방침 보완: 접속 주소·2년 이상, 국외 이전 고지 표(이전받는 자·나라·정보·시기·목적·보유기간·거부 방법), 동의 기록 안내, 개정 이력 |
| 4 | 동의 기록: 교적 카드의 '동의 기록'은 이미 있었고, 처리방침 판을 `POLICY_VERSION` 상수로 통일. 명단 › **개인정보 동의** 탭 신설(동의 빠진 재적 교인, 14세 미만은 보호자 동의 포함) |
| 5 | `docs/privacy-forms.html`: 등록카드 동의 문구, 14세 미만 보호자 동의서, 유출 대응 한 장, 연간 점검표(인쇄용) |
| 보류 | 담당자 2단계 인증(사용자 결정으로 우선 보류) |

### 부록: 교적 동의 표 `cm_consents` (참고용, 쓰기는 교적만)
`id CHAR(36)`, `seq`, `person_id CHAR(36)`(→ cm_people), `kind`(교적 등록·민감정보·요람 공개·보호자 동의), `policy_version VARCHAR(30)`, `consent_date DATE`, `method`(서면·앱·구두), `guardian_name VARCHAR(50)`, `revoked_on DATE`.
**dm/fin 은 `cm_` 표를 읽기만** 하고 쓰지 마세요(기존 약속). 동의를 부서·재정에서 남겨야 한다면 별도 표를 만들거나, 교적에 "동의 기록 추가 API" 를 요청하세요(교적 세션에서 만들어 드립니다).
