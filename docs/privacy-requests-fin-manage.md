# 재정 관리(fin-manage) 개인정보 보강 수정 요청

작성: 2026-11-17 (교적 관리 ch-manage 세션) · 이 파일은 **fin-manage 세션에 그대로 붙여 넣어** 수정을 지시하는 용도입니다.
짝 파일: docs/privacy-requests-dm-manage.md (부서 관리용)

> 이 문서의 법령 내용은 웹 검색으로 확인한 요약이며 **조문 원문을 직접 읽은 것이 아닙니다.** 법률 자문이 아닙니다.
> "확인 필요"로 표시한 것은 법제처(law.go.kr)·개인정보보호위원회(privacy.go.kr) 원문 확인 후 적용하세요.
> **지시 방식**: 아래 2번의 항목을 우선순위 순서로 진행하되, 설계가 필요한 항목(동의 기록 등)은 구현 전에 **설계안을 사용자에게 먼저 보여 주고 확인**을 받으세요. 커밋·푸시·배포는 사용자가 말할 때만 하세요. 2단계 인증은 이번 범위에서 **제외(보류)** 입니다.

## 1. 공통 배경 (법 기준과 교적이 정한 약속)

### 적용되는 법과 기준
| 구분 | 요구 | 근거 |
|---|---|---|
| 처리방침 | 모든 개인정보처리자가 수립·공개 | 개인정보 보호법 제30조 |
| 보호책임자 | 지정하고 연락처 공개 | 제31조 |
| 민감정보 | 종교 관련 정보는 민감정보로 보는 것이 일반적. 별도 동의 | 제23조 |
| 14세 미만 | 법정대리인 동의 | 제22조의2 |
| 국외 이전 | 이전받는 자·국가·시기·방법·항목·목적·보유기간·거부 방법 공개 | 제28조의8 |
| 파기 | 목적이 끝나면 지체 없이 | 제21조 |
| 접속기록 | **1년 이상, 민감정보·고유식별정보를 처리하는 시스템은 2년 이상.** 항목: 계정, 접속일시, **접속지 정보(IP)**, 처리한 정보주체 정보, 수행 업무 | 안전성 확보조치 기준 제8조 (확인 필요: 2년 기준 세부) |
| 접근권한 변경 기록 | 부여·변경·말소 내역 **3년 이상** | 같은 기준 제5조 제3항 (확인 필요) |
| 유출 | 정보주체 통지 + 일정 규모 이상 신고(1천 명 이상 등) | 제34조 (통지 기한이 자료마다 24시간·72시간으로 달라 **원문 확인 필요**) |

2026년 9월 11일 시행된 개정 보호법: 과징금 강화, 유출 통지 범위 확대(랜섬웨어 등 포함), 대표자 책임 강화. 교회에 어디까지 적용되는지는 확인하지 못함.

### 교적(ch-manage)이 정한 공통 약속 — 두 프로그램도 맞춰 주세요
1. **책임자·문의처는 교적의 교회 정보에서 가져옵니다.** 교적 0.1.1부터 `cm_site_settings.church_info` JSON 에 새 칸이 있습니다.
   - `privacyOfficer` (개인정보 보호책임자: 직책·이름), `privacyPhone`, `privacyEmail`
   - 비어 있으면 `phone`, `email`(교회 대표 전화·이메일)로 대신합니다. 교적은 `/auth/me` 응답에 이미 `privacy: {officer, phone, email}` 로 합쳐서 내려 줍니다. (읽기만 하세요. 쓰지 마세요.)
2. **접속·수정 기록 보관은 최소 2년.** 교적은 기본 3년, 설정 범위 2~10년.
3. **처리방침 판(시행일)** 은 `YYYY-MM-DD` 하나로 관리하고, 방침 화면의 날짜와 동의 기록의 "처리방침 판"이 같은 값을 쓰게 합니다. (교적: `POLICY_VERSION = '2026-11-17'`)
4. 방침에 **개정 이력** 목록을 둡니다(날짜 · 한 줄 요약).
5. 접속 기록에는 접속 주소(IP)를 남깁니다.
6. **2단계 인증은 보류**입니다(이번 요청에 포함하지 않음).

## 2. 수정 요청 (재정 관리)

### 배경
재정 관리는 **개인별 헌금 내역(헌금자 이름·금액·날짜)** 과 **기부금 영수증용 주민등록번호** 를 다룹니다. 개인별 헌금은 종교 활동과 직결되어 **민감정보로 취급하는 것이 안전**합니다. 이미 `access_log`(IP 포함), 주민번호 암호화 또는 "보관 안 함" 선택, 방침 화면(`src/routes/privacy/+page.svelte`)이 있습니다. 아래는 보완할 부분입니다.

### 수정 요청 (우선순위 순)

**F-1. 접속기록 보관 2년 이상 명시와 동작 확인** — `access_log` 를 지우는 코드는 현재 보이지 않습니다(무기한 보관으로 보임). 방침의 보관 기간 문구가 실제와 같은지 확인하고 **"2년 이상"** 을 명시하세요. 나중에 정리 기능을 만들 때는 2년 미만으로 줄일 수 없게 하세요. `change_log`(헌금·거래·예산·담당자 수정 전후)도 같은 기준으로 보관 기간을 적으세요.

**F-2. 개인별 헌금 열람 기록 점검** — 법이 요구하는 항목(계정, 시각, IP, 처리한 정보주체, 수행 업무)이 개인별 헌금 열람·내려받기(엑셀/CSV)·주민번호 사용·영수증 발급·권한 변경 모두에 남는지 확인하세요. 빠진 것이 있으면 추가. 특히 **대량 내려받기(CSV)** 는 사유를 묻거나 최소한 기록에 남기는 것을 권장합니다(확인 필요: 다운로드 사유 확인 기준).

**F-3. 민감정보 안내** — 방침에 "개인별 헌금 내역은 종교 활동과 관련된 민감정보로 보고, 개인별 열람 권한을 지정된 사람에게만 주며 열람할 때마다 기록한다"를 명시하세요. 교적의 **'민감정보' 동의**(교적 카드 동의 기록)와 어떻게 연결되는지(헌금자가 교적 교인일 때) 한 줄로 안내. 헌금자 동의 확인 화면을 추가할지는 설계를 먼저 사용자에게 보여 주세요.

**F-4. 주민등록번호 보유 기간과 법적 근거** — 기부금 영수증 발급에는 법령상 근거가 있어 주민번호를 처리할 수 있지만, 방침에 **법적 근거와 보유 기간**을 구체적으로 적으세요. (확인 필요: 기부금영수증 발급명세 작성·보관 의무 — 소득세법 시행령, 보통 발급일부터 5년.) "보관 안 함" 선택 시의 처리와 "암호화 보관" 선택 시 파기 시점(기간 지난 번호 정리 기능이 있다면 그 기간)을 같은 곳에 적고, 기간이 법정 보관 기간보다 짧지 않은지 점검하세요.

**F-5. 접근권한 부여·변경·말소 기록 3년** — 재정 사용 승인·역할 지정·권한 변경 기록(`change_log` 또는 `access_log`)을 **3년 이상** 보관하는지 확인하세요(확인 필요: 안전성 확보조치 기준 제5조 제3항).

**F-6. 책임자·문의처를 교적 새 칸으로** — 방침 12번이 "책임자·연락처는 교적의 교회 정보에서 가져온다"고 되어 있는데, 가져오는 칸을 **`privacyOfficer`, `privacyPhone`, `privacyEmail`**(없으면 `phone`, `email`)로 바꾸세요. 교적은 로그인 전에도 `/auth/me` 로 합친 값을 줍니다. (읽기만)

**F-7. 방침 판·개정 이력** — 시행일 `YYYY-MM-DD` 한 곳 관리 + "개정 이력" 목록. 이번 개정(접속기록 2년 이상, 민감정보 안내, 주민번호 보유 기간 구체화)을 한 줄로.

**F-8. 위탁·국외 이전 확인** — 증빙 사진, 문자, 은행 연동 등 **외부로 정보가 나가는 기능**이 있는지 확인하세요(현재는 없는 것으로 보임). 있으면 표로 공개. 없으면 "외부로 보내지 않는다"를 명시.

**F-9. 유출 대응 안내** — 관리자용 문서에 "유출 의심 시 순서"(계정 막기 → 기록 보존 → 책임자 보고 → 교인 통지 → 신고)를 넣거나 교적 `docs/privacy-forms.html` 3쪽을 가리키세요. 재정은 주민번호가 있어 사고 시 파급이 큽니다.

### 확인 방법(수정 후)
- 개인별 헌금 열람·내려받기·영수증 발급이 IP와 함께 기록되는지
- 방침 화면: 접속기록 2년 이상, 주민번호 법적 근거·보유 기간, 개정 이력, 책임자·문의처(교적 값)
- 교적 없이 단독 설치한 경우에도 방침이 깨지지 않는지(문구 대체)

## 3. 교적(ch-manage)에서 한 일 (참고)

| 번호 | 내용 |
|---|---|
| 1 | 접속·수정 기록 보관 설정 최소 **2년**(서버 `LOG_YEARS_MIN`, 화면 입력칸 min=2). 예전에 1년으로 저장돼 있어도 읽을 때 2년으로 보정 |
| 2 | 접속 기록에 **접속 주소(IP)** 추가(마이그레이션 008, 구조 번호 8). 관리자 화면 접속 기록 표에 "접속 주소" 열 |
| 3 | 처리방침 보완: 접속 주소·2년 이상, 국외 이전 고지 표(이전받는 자·나라·정보·시기·목적·보유기간·거부 방법), 동의 기록 안내, 개정 이력 |
| 4 | 동의 기록: 교적 카드의 '동의 기록'은 이미 있었고, 처리방침 판을 `POLICY_VERSION` 상수로 통일. 명단 › **개인정보 동의** 탭 신설(동의 빠진 재적 교인, 14세 미만은 보호자 동의 포함) |
| 5 | `docs/privacy-forms.html`: 등록카드 동의 문구, 14세 미만 보호자 동의서, 유출 대응 한 장, 연간 점검표(인쇄용) |
| 보류 | 담당자 2단계 인증(사용자 결정으로 우선 보류) |

### 부록: 교적 동의 표 `cm_consents` (참고용, 쓰기는 교적만)
`id CHAR(36)`, `seq`, `person_id CHAR(36)`(→ cm_people), `kind`(교적 등록·민감정보·요람 공개·보호자 동의), `policy_version VARCHAR(30)`, `consent_date DATE`, `method`(서면·앱·구두), `guardian_name VARCHAR(50)`, `revoked_on DATE`.
**dm/fin 은 `cm_` 표를 읽기만** 하고 쓰지 마세요(기존 약속). 동의를 부서·재정에서 남겨야 한다면 별도 표를 만들거나, 교적에 "동의 기록 추가 API" 를 요청하세요(교적 세션에서 만들어 드립니다).
