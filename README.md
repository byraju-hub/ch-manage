# ch-manage
교회 교적 관리 시스템

교인 명단(교적 카드), 출석, 심방, 공동체·소그룹, 교회 조직, 증명서·명단 출력을 관리하는 교역자와 교적 담당자를 위한 웹 프로그램입니다. cafe24와 같은 PHP + MariaDB 웹호스팅에 설치해서 사용하고, 무료로 배포합니다.

교회 부서(유치부·유초등부·중고등부·청년부 등)를 관리하는 [dep-manage](https://github.com/byraju-hub/dep-manage)와 짝을 이루는 프로그램입니다. 따로 써도 되고, 같은 교회에서 둘 다 쓰면 교육부서 학생·교사 자료를 서로 맞춰 쓸 수 있습니다. ([함께 쓰기](#dep-manage-와-함께-쓰기))

- 구조 설계: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md)
- 진행 계획: [PLAN.md](PLAN.md)
- 소개 페이지: [site/](site/index.html) (Cloudflare Pages에 `site` 폴더를 그대로 올립니다)
- 라이선스: [GNU AGPL-3.0](LICENSE)

## 지금 되는 것

- **설치 마법사** (`/install/`): DB 정보, 교회 이름과 모임 이름(공동체·교구·지역 / 소그룹·구역·목장·셀), 최고관리자 계정을 입력하면 끝. 모든 표 이름에 접두어(기본 `cm_`)를 붙여 같은 DB의 다른 프로그램과 섞이지 않습니다. 체험용 샘플 데이터는 대시보드에서 불러오고, 한 번에 지울 수 있습니다.
- **로그인과 권한**: 아이디·비밀번호 로그인, 가입 신청 → 최고관리자 승인, 등급 A(전임 교역자) · B(교적 관리) · C(열람) · **D(소그룹 인도자: 교적 화면은 열 수 없고, 자기 소그룹의 주일 출석 체크만)**. 등급마다 할 수 있는 일(수정·내려받기·사이트 관리)은 최고관리자가 정하고, **심방은 A 등급만** 볼 수 있습니다. 모든 권한은 서버가 요청마다 다시 확인하고, 심방·인도자 특이사항·이전 프로그램 메모는 권한이 없는 사람에게는 아예 내려보내지 않습니다. 비밀번호를 잊으면 최고관리자가 임시 비밀번호를 만들어 줍니다.
- **교적**: 교인 목록(무엇이든 검색·여러 조건 필터·엑셀 내려받기·일괄 수정), 교적 카드(사진, 재적·신급·직분 이력, 세대, 메모·동의, 변경 이력), 교인 등록(동명이인 자동 구분), 새가족 정착, 세대 목록.
- **공동체·소그룹**: 편성표, 소그룹 페이지(출석률), 소그룹별 명단(인쇄·엑셀·PDF), 인도자 특이사항(A 등급).
- **출석**: 주일 오전예배 출석 체크와 전체 인원, 주일 오후 소그룹 출석, 출석 추이·장기 결석 알림. 출석 기록이 없는 주일은 '기록 없음'으로 보고 결석으로 세지 않습니다.
- **심방**(A 등급): 심방 기록, 캘린더 보기, 심방 내용에서 입원·수술 같은 일정을 뽑아 성도 일정으로.
- **캘린더·조직·통계**: 교회 절기·성례·사역·심방·성도·생일·공휴일 캘린더, 교회 조직표·당회·시무집사회·시무권사회·서리집사·전도회, 주일 출석·임직·세례 통계.
- **문서 출력**: 교적부, 교인증명서, 세례증명서, 기부금 영수증, 교인 요람, 생일·직분자 명단 (인쇄·PDF).
- **설정**: 교회 정보·로고·직인, 증명서 양식, 연간 설정(표어, 나이 계산 방식, 출생 연도별 공동체·전도회, 교육부서 기준, 연간 계획표 엑셀 등록), 교인구분·코드표, 데이터 전체 내려받기.
- **dep-manage 연동**: 같은 DB에 부서 관리가 설치되어 있으면 학생·교사를 교인과 연결해서, 교적에서 고친 인적사항이 부서 관리에 맞춰지고 부서 관리의 출석을 교적 화면에서 볼 수 있습니다. 사진은 한쪽에만 있으면 다른 쪽으로 복사하고, 학생이 승급해 부서가 바뀌면 교적의 교육부서를 부서 관리에 맞춥니다. ([함께 쓰기](#dep-manage-와-함께-쓰기))
- **여러 명이 함께**: 바뀐 칸만 서버에 저장하므로 서로 다른 칸을 고치면 덮어쓰지 않고, 다른 사람이 저장하면 1분 안에 화면에 반영됩니다.
- **백업과 되살리기** (최고관리자): 모든 자료(교인·출석·심방·사용자·접속 기록)와 올린 그림을 파일 하나(`.cmbak`)로 내려받고, 그 파일이나 서버에 보관한 백업으로 되살립니다. 자동 백업은 호스팅의 예약 작업 없이, 누군가 프로그램을 쓰는 중에 때가 되면 서버가 만들고 보관 개수를 지킵니다. 되살리기 직전의 자료는 자동으로 한 번 더 보관됩니다.
- **개인정보 정리**: 전출·별세·제적 후 정한 기간(기본 5년)이 지난 교인의 인적사항(연락처·주소·생년월일·직업·메모·사진·수정 이력)을 지우고 교회 기록(이름·재적·세례·직분)은 보관합니다. 오래된 접속·수정 기록(기본 3년)도 정리합니다. 샘플 교인은 건드리지 않고, 정리 직전 자료를 서버에 보관합니다.
- **증명서 발급 번호**: 증명서를 출력할 때마다 서버가 올해 안에서 겹치지 않는 번호를 정해 발급 대장에 남깁니다.
- **외부 서비스(선택)**: 교회가 자기 키를 넣으면 켜집니다 (관리자 › 프로그램 설정 › 외부 서비스). 설정하지 않으면 해당 버튼은 화면에 나타나지 않습니다. ① 문자 발송(솔라피, A 등급·하루 3,000건 한도·수신 거부는 서버도 거름), ② AI 분석(구글 Gemini): 등록카드 사진으로 교인 등록 칸 채우기, 심방 녹음·문서로 심방 기록 채우기. 키는 서버에만 저장하고 백업 파일에도 넣지 않습니다. 큰 파일은 60KB 조각으로 올립니다(호스팅의 128KB 한도).

## 알아둘 점

- 문자(솔라피)와 AI(Gemini) 연결은 실제 서비스 키로 시험하기 전입니다. 서비스 주소·응답 모양을 흉내 낸 시험 서버로는 확인했으니, 처음 연결할 때 '저장하고 연결 확인'이 통과하는지, 한두 명에게 먼저 보내 보는지 확인해 주세요.
- 자동 백업·개인정보 정리는 호스팅의 예약 작업(cron)이 아니라 '사용 중에 확인'하는 방식이라, 아무도 접속하지 않으면 다음 접속 때 실행됩니다.

## 구조

```
src/      SvelteKit 정적 앱 (adapter-static). 서버의 PHP API(/api/v1)와 이야기합니다.
server/   PHP API, 설치 마법사, 데이터베이스 구조(migrations). 사이트 폴더에 그대로 올립니다.
docs/     설계 문서
site/     소개 페이지(정적 한 장). Cloudflare Pages: 빌드 명령 없음, 출력 폴더 `site`
static/   로고·아이콘 등 정적 파일
```

## dep-manage 와 함께 쓰기

두 프로그램을 **같은 데이터베이스**에 설치하면(표 이름 접두어가 달라 섞이지 않습니다: 교적 `cm_`, 부서 관리 `dm_`) 설치 순서와 상관없이 연결할 수 있습니다. 한쪽만 쓰는 교회에는 아무 영향이 없습니다.

1. 교적에 로그인한 최고관리자가 **관리자 › 프로그램 설정 › 부서 관리 연결** 을 엽니다. (부서 관리가 같은 DB에 있을 때만 나타납니다)
2. **연결할 후보 불러오기**: 이름과 생년월일이 같으면 '확실'(한꺼번에 연결), 이름만 같으면 직접 고르고, 한쪽에만 있으면 상대쪽에 만들 수 있습니다.
3. 연결한 뒤에는 항목별로 주인이 나뉩니다.

| 항목 | 주인 |
|---|---|
| 이름·성별·생년월일·연락처·주소·세례 | **교적**. 교적에서 저장하면 연결된 학생·교사에게 바로 맞춰집니다 (비어 있는 연락처·주소는 부서 관리의 값을 지우지 않습니다). 부서 관리에서는 이 칸들이 잠깁니다. |
| 부서·학년·반·출석·부서 심방 | **부서 관리**. 교적은 바꾸지 않고, 부서 관리의 출석을 교적 카드와 교육부서 통계에서 읽어 보여 줍니다. |

교적의 교육부서와 부서 관리의 부서 이름이 다르면 연결 목록에 "확인 필요"로 알려 줍니다. dep-manage는 이 기능이 들어간 버전이어야 하고, 부서 관리 쪽 DB 구조가 달라서 읽을 수 없으면 연동만 조용히 꺼집니다(교적은 그대로 동작합니다). 사진은 한쪽에만 있을 때 다른 쪽으로 복사합니다(같은 호스팅 계정에서 부서 관리의 data 폴더를 자동으로 찾고, 못 찾으면 경로를 직접 알려 주면 됩니다). 양쪽에 있으면 그대로 둡니다.

## 설치해서 쓰기

[Releases](https://github.com/byraju-hub/ch-manage/releases)에서 `ch-manage-vX.Y.Z.zip` 을 받아 압축을 풀고, 안의 내용을 호스팅 사이트 폴더에 올린 뒤 `/install/` 을 열면 됩니다. 자세한 순서는 zip 안의 `설치가이드.pdf` ([소스](docs/install-guide.html), [PDF](docs/설치가이드.pdf)) 를 보세요.

1. 사이트 폴더(예: `www/cm`)에 zip 안의 내용을 모두 올립니다. (직접 만들 때는 `build/`와 `server/`의 내용)
2. 브라우저로 `https://내도메인/cm/install/` 을 열고 안내를 따릅니다. (환경 점검 → 데이터베이스 → 교회 정보 → 관리자 계정)
3. 새 버전으로 바꿀 때는 파일을 덮어쓴 뒤 `/install/` 을 한 번 열면, 화면 파일의 폴더 주소를 마무리하고 데이터베이스 변경이 있으면 함께 적용합니다. (설정과 자료는 그대로 남습니다.)

서버 요구사항: PHP 8.1 이상 (8.4에서 확인, `pdo_mysql`·`mbstring` 필요, `gd`·`curl` 권장), MariaDB 10.x / MySQL, Apache mod_rewrite.

> **카페24 호스팅 참고:** 카페24는 요청 하나의 크기가 128KB를 넘으면 서버에 닿기 전에 막습니다. ch-manage는 저장할 때 100KB 이하로 나눠 보내고, 로고·직인 그림은 자동으로 줄여 올립니다.

## 개발과 배포

```
npm install
npm run dev                                   # 화면 (http://localhost:5173) — /api 는 아래 PHP 서버로 넘어갑니다
php -S 127.0.0.1:8090 -t server server/dev-router.php   # 다른 터미널: PHP API + 설치 마법사 (http://127.0.0.1:8090/install/)

BASE_PATH=/__CM_BASE__ npm run build          # build/ 에 정적 파일 생성 (폴더 주소는 설치할 때 실제 폴더로 바뀝니다)
BASE_PATH=/cm npm run build                   # 폴더 이름을 이미 알고 있다면 직접 지정해도 됩니다
```

Windows의 Git Bash에서는 `/`로 시작하는 값이 경로로 바뀌므로 `MSYS_NO_PATHCONV=1 BASE_PATH=/__CM_BASE__ npm run build` 처럼 앞에 붙입니다. 로컬에 PHP·MariaDB가 있다면 위 두 서버로 설치부터 전부 시험할 수 있습니다.

화면 코드를 고칠 때 지킬 것:
- 내부 링크는 `href="/…"` 가 아니라 `hrefTo('/…')` (`src/lib/registry/paths.ts`)를 거칩니다. 사이트를 서브폴더에 올려도 주소가 맞아야 하기 때문입니다.
- 화면의 데이터 칸을 바꾸면 서버의 표 정의(`server/api/lib/data.php`의 `data_specs()`)와 화면 쪽 변환(`src/lib/registry/tables.ts`)을 함께 고칩니다. 서버에 없는 칸은 저장이 거절됩니다.
